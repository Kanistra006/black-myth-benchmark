# WukongBenchRunner

Консольный инструмент на C# (.NET 8), который полностью автоматически выполняет два прохода
**Black Myth: Wukong Benchmark Tool** из Steam — **CPU-тест** и **GPU-тест** — и выводит отчёт:
характеристики компьютера, результаты обоих тестов и настройки, с которыми они выполнялись.

```
dotnet run --project src/WukongBenchRunner -c Release
```

Запуск → настройка → прохождение меню → ожидание конца теста → разбор результатов → второй проход →
отчёт. Вмешательство пользователя не требуется, исходные настройки бенчмарка в конце восстанавливаются.

---

## Требования

| | |
|---|---|
| ОС | Windows 10/11 x64 |
| .NET | [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0) (или новее) |
| Steam | запущен, выполнен вход в аккаунт |
| Бенчмарк | [Black Myth: Wukong Benchmark Tool](https://store.steampowered.com/app/3132990/) (бесплатный, AppID 3132990) установлен и **хотя бы один раз запущен вручную** — при первом запуске игра создаёт свой файл настроек и компилирует шейдеры |

## Запуск

```powershell
git clone <url-репозитория> WukongBenchRunner
cd WukongBenchRunner
dotnet run --project src/WukongBenchRunner -c Release
```

Ничего выбирать не нужно: инструмент показывает, что будет сделано, даёт 5 секунд на отмену (Ctrl+C) и дальше
работает сам. Пока идёт тест (около 8 минут на два прохода), **не трогайте мышь и клавиатуру и не блокируйте
Windows**: инструмент управляет меню игры кликами и нажатиями клавиш. Ноутбук должен быть подключён к зарядке.
Ctrl+C в любой момент закрывает игру и восстанавливает настройки.

Результаты:

* в консоли — таблицы с характеристиками ПК, результатами и настройками;
* в папке `results\<дата-время>\`:
  * `report.md` — тот же отчёт в Markdown;
  * `report.json` — все данные в машиночитаемом виде;
  * `cpu-pass.raw.json`, `gpu-pass.raw.json` — исходные файлы результатов бенчмарка (с покадровыми данными);
  * `GameUserSettings.backup.ini` — резервная копия исходных настроек игры.

Параметры командной строки (все необязательные):

| Параметр | Назначение |
|---|---|
| `--game-dir <путь>` | папка Benchmark Tool, если не удаётся найти её через Steam |
| `--output <путь>` | папка для отчёта |
| `--only cpu` / `--only gpu` | выполнить только один проход |
| `--direct-launch` | запускать exe игры напрямую, а не через `steam://` |
| `--keep-settings` | не восстанавливать исходные настройки бенчмарка |
| `--no-countdown` (`-y`) | стартовать сразу, без 5-секундного отсчёта |
| `--cpu-window <ШxВ>` / `--cpu-window desktop` | размер окна CPU-теста (по умолчанию 1280x720) или окно без рамок на весь экран |
| `--cpu-scale <25-100>` | масштаб рендера CPU-теста в процентах (по умолчанию 25) |
| `--gpu-rt off\|low\|medium\|ultra` | уровень полной трассировки лучей в GPU-тесте (по умолчанию выбирается по объёму видеопамяти) |

Тесты: `dotnet test`.

## Как это работает

### 1. Поиск бенчмарка

Путь к Steam берётся из реестра (`HKCU\Software\Valve\Steam\SteamPath`), библиотеки — из
`steamapps\libraryfolders.vdf`, папка игры — из `appmanifest_3132990.acf`.

### 2. Изменение настроек

Benchmark Tool — игра на Unreal Engine 5. Все настройки из её меню хранятся в
`<папка игры>\b1\Saved\Config\Windows\GameUserSettings.ini`, причём в двух местах, которые должны совпадать:

* `UISettingData=(("QualityLevel", "5"),("Rtx", "1"),...)` — значения пунктов меню игры;
* `[ScalabilityGroups] sg.*` — стандартные группы масштабируемости Unreal Engine, по которым идёт рендеринг.

Соответствие значений определено экспериментально — изменением каждого пункта в меню игры и сравнением файла:

| Ключ `UISettingData` | Пункт меню | Значения |
|---|---|---|
| `QualityLevel` | Набор настроек графики | 1 Низк., 2 Средн., 3 Высок., 4 Оч. высок., 5 Кинематогр. («Реалистичн.»), 6 Пользовательский |
| `ViewDistance`, `ShadowQuality`, `TextureQuality`, `FxQuality`, `VegetationQuality`, `GlobalIllumination`, `ReflectionQuality`, … | отдельные параметры качества | 1…5 (как выше); в `sg.*` записывается на единицу меньше (0…4) |
| `SuperResolutionSampling` | Избыточная выборка сглаживания | 0 FSR, 1 XeSS, 2 DLSS, 3 TSR |
| `ImageQuality` + `sg.ResolutionQuality` | Степень избыточной выборки (масштаб рендера 25…100%) | высота рендера в пикселях + процент |
| `InsertFrame` | Генерация кадров | 0 / 1 |
| `Rtx`, `RtxLevel` + `r.RayTracing.EnableInGame` | Полная трассировка лучей и её уровень | 0 / 1; 1 Низк., 2 Средн., 3 Ультра |
| `ScreenMode` + `FullscreenMode` | Режим отображения | 0 полный экран, 1 окно без рамок, 2 оконный |
| `Vsync`, `LockFrameRate` | VSync, ограничение FPS | 0 = выкл. |

Кроме этого выставляются `FirstSettingFinish=True` и `AgreementReaded=1`, чтобы игра не показывала экраны
первичной настройки (язык, яркость, соглашение). Согласие на сбор данных (`PrivacyAgreement`) не меняется.

Перед первым проходом файл копируется в папку отчёта и в конце (в том числе при ошибке или Ctrl+C)
восстанавливается.

Каждый проход начинается с «холодного» запуска игры, поэтому новые настройки гарантированно применяются.

### 3. Запуск

Игра запускается через `steam://rungameid/3132990`. Прямой запуск `b1_benchmark.exe` вызывает в Steam
диалог «Запустить игру с пользовательскими параметрами», который требует ручного подтверждения;
запуск через протокол Steam этого избегает (`--direct-launch` оставлен как альтернатива).

### 4. Старт теста

Параметров командной строки или настроек для автозапуска теста у Benchmark Tool нет, поэтому инструмент
проходит меню сам, как пользователь:

1. ждёт окно игры и пропускает ~20 секунд чёрных экранов загрузки и логотипов: действовать начинает, когда
   окно три проверки подряд показывает обычное изображение (титульный экран, меню или экран компиляции шейдеров);
2. нажимает **E** (экран «Нажмите любую кнопку»), кликает **«Тест быстродействия»** в главном меню и
   **«Подтвердить»** в диалоге;
3. считает тест начатым, когда окно становится чёрным (экран загрузки тестовой сцены) и игра перезаписывает
   `GameUserSettings.ini` — оба события происходят сразу после подтверждения;
4. если тест не начался (меню ещё не появилось, идёт компиляция шейдеров), повторяет шаги 2–3;
5. если результат так и не появился, проход один раз повторяется с нового запуска игры.

Яркость измеряется по содержимому самого окна игры (`PrintWindow`), а не по участку экрана, поэтому другие
окна поверх игры на детектор не влияют.

Клавиши отправляются как аппаратные скан-коды через `SendInput` (Unreal читает raw input),
клики — реальным курсором. Координаты элементов меню измерены в базовом макете игры 1280x720 и
пересчитываются под реальный размер окна (интерфейс масштабируется по высоте), поэтому работают при
любом разрешении.

### 5. Получение результатов

После каждого прохода бенчмарк сохраняет файл `%TEMP%\b1\BenchMarkHistory\Tool\<unix-время>` — это JSON
без расширения:

```json
{"FPSAvg":103,"FPSMax":131,"FPSMin":55,"FPS95":91,"GPUAvg":93,"VideoMem":4.0,
 "CPUModel":"...","GPUModel":"...","ScreenResolution":"2560 × 1440","QualityLevel":1,"ImageQuality":25,
 "Rtx":0,"InsertFrame":0,...,
 "Records":[{"FrameRate":100.2,"CPUFrameTime":8.43,"GPUFrameTime":8.85,"GPUUsage":94.0,...}, ...]}
```

Инструмент ждёт появления нового файла, разбирает его и закрывает игру. Из файла берутся:

* **показатели самого бенчмарка** — средний, минимальный, максимальный FPS, 5-й перцентиль, объём использованной видеопамяти;
* **настройки, которые игра реально применила** (пресет и отдельные параметры, масштаб рендера, разрешение,
  уровень RT — поле `Rtx`, апскейлер — поле `Dlss`, генерация кадров) — в отчёте они выводятся в скобках
  «(игра: …)» рядом с запрошенными, это проверка того, что настройки действительно вступили в силу;
* **покадровые записи**, по которым дополнительно считается 1% low FPS.

Параллельно, пока идёт тест, инструмент раз в секунду сам замеряет загрузку CPU (счётчики Windows: среднее
по всем ядрам и самое загруженное ядро) и, на видеокартах NVIDIA, загрузку/частоту/мощность/температуру GPU
через `nvidia-smi`. Эти независимые замеры показывают, какой компонент на самом деле был узким местом.

## Выбор настроек

Главное правило обоих проходов — **генерация кадров, VSync и ограничение FPS выключены**. Генерация кадров
вставляет «нарисованные» промежуточные кадры: на тестовом ПК со стандартными настройками бенчмарк показал
59 FPS при реальных ~30 отрендеренных кадрах в секунду. Такой FPS не отражает производительность ни CPU, ни GPU.

### CPU-тест: минимум работы для видеокарты

| Параметр | Значение | Почему |
|---|---|---|
| Режим | оконный, 1280x720 | постобработка, апскейл и интерфейс считаются в разрешении вывода; маленькое окно убирает эту нагрузку |
| Масштаб рендера | 25% (минимум игры) → 320x180 | стоимость кадра для GPU почти полностью зависит от числа пикселей |
| Апскейлер | FSR | самый дешёвый и работает на любой видеокарте |
| Пресет | Низкий (все параметры) | минимум теней, освещения, отражений, эффектов |
| Трассировка лучей | выкл. | |
| Генерация кадров / VSync / лимит FPS | выкл. | |

Логика: игровая логика, анимация, физика, стриминг уровня и подготовка draw call'ов на CPU от разрешения не
зависят, а работа GPU уменьшается в десятки раз. Видеокарта успевает раньше процессора, и FPS определяется
скоростью CPU.

Как выбор проверялся на тестовом ПК (i5-12450H, RTX 4060 Laptop 8 ГБ, монитор 2560x1440):

| Вариант CPU-теста | Средний FPS | Время кадра CPU / GPU (по данным игры) | Загрузка CPU (все ядра) | Загрузка GPU |
|---|---:|---:|---:|---:|
| окно без рамок 2560x1440, масштаб 25% (рендер 640x360) | 103 | 8,8 / 8,3 мс | — | 93 % (игра) |
| **оконный 1280x720, масштаб 25% (рендер 320x180)** | **105–118** | **8,5–9,6 / 5,3–5,5 мс** | **99–100 %** | **67–76 %** (nvidia-smi) |

В первом варианте GPU почти не отставал от CPU: постобработка, апскейл до 2560x1440 и вывод на экран
занимали ~8 мс на кадр. В выбранном варианте GPU тратит на кадр почти вдвое меньше времени, чем CPU,
процессор загружен полностью — FPS определяется процессором.

### GPU-тест: максимум работы для видеокарты

| Параметр | Значение | Почему |
|---|---|---|
| Режим | окно без рамок, разрешение рабочего стола (нативное) | максимум пикселей, которые реально выводятся на монитор |
| Масштаб рендера | 100% | рендер в полном разрешении, без апскейла |
| Апскейлер / сглаживание | TSR на 100% | временное сглаживание Unreal в нативном разрешении — самое тяжёлое из доступных и не зависит от производителя GPU |
| Пресет | Кинематографический (все параметры) | максимум теней, GI, отражений, растительности, эффектов |
| Полная трассировка лучей | максимальный уровень, который помещается в видеопамять: ≥12 ГБ — «Ультра», 8–12 ГБ — «Средн.», меньше или не NVIDIA RTX — выкл. | самая тяжёлая для GPU функция игры (доступна только на NVIDIA RTX) |
| Генерация кадров / VSync / лимит FPS | выкл. | |

Почему уровень трассировки лучей выбирается по объёму видеопамяти, а не всегда «Ультра» — замеры на тестовом
ПК (кинематографический пресет, 2560x1440, TSR 100%):

| Полная трассировка лучей | Средний FPS | Видеопамять | Загрузка GPU (nvidia-smi) | Мощность GPU |
|---|---:|---:|---:|---:|
| выкл. | 12 | 6,2 ГБ | 99,3 % | 39,7 Вт |
| «Низк.» | 9 | 7,2 ГБ | 98,9 % | 40,2 Вт |
| **«Средн.»** | **9** | **7,2 ГБ** | **98,9 %** | **39,9 Вт** |
| «Ультра» | 5 | 7,6 из 8 ГБ | 86 % | 37,4 Вт |

С «Ультра» кадр перестаёт помещаться в 8 ГБ видеопамяти: данные гоняются по PCIe, видеокарта простаивает
в ожидании, её загрузка и потребление падают. Такой тест измеряет нехватку памяти, а не производительность
GPU. Поэтому выбирается самый тяжёлый вариант, при котором память ещё не переполнена, а GPU загружен на ~99 %.
Если в проходе всё-таки занято ≥94 % видеопамяти, отчёт выводит предупреждение. Уровень можно задать вручную:
`--gpu-rt off|low|medium|ultra`.

CPU при этом в основном простаивает (30–50 % в среднем по ядрам при FPS ~9): узким местом является только GPU.

## Пример отчёта

Полный отчёт реального запуска — [docs/sample-report.md](docs/sample-report.md). Основная таблица
(i5-12450H, RTX 4060 Laptop 8 ГБ, 16 ГБ DDR5-4800, монитор 2560x1440):

| Показатель | CPU-тест | GPU-тест |
|---|---:|---:|
| Средний FPS | 118 | 9 |
| Минимальный FPS | 24 | 6 |
| Максимальный FPS | 152 | 11 |
| 5-й перцентиль FPS | 94 | 8 |
| 1% low FPS (по кадрам) | 70 | 7,7 |
| Видеопамять, ГБ | 3,8 | 7,3 |
| Загрузка GPU (nvidia-smi), % | 75,7 | 98,7 |
| Загрузка CPU (все ядра), % | 98,7 | 28,5 |
| Загрузка самого занятого ядра CPU, % | 100 | 75 |

Нагрузка распределена так, как задумано: в CPU-тесте процессор загружен полностью, в GPU-тесте видеокарта
загружена на ~99 %, а процессор почти простаивает. Между повторными запусками на ноутбуке средний FPS
CPU-теста колебался в пределах 105–118 — сказывается нагрев (GPU держится около 90 °C).

```

  Program.cs                 сценарий: бэкап → CPU-проход → GPU-проход → восстановление → отчёт
  CliOptions.cs              параметры командной строки
  Game/GameLocator.cs        поиск бенчмарка через Steam
  Settings/
    IniDocument.cs           редактор INI с сохранением форматирования
    UiSettingData.cs         разбор/сборка значения UISettingData

  Automation/

  Results/
    BenchmarkHistoryFile.cs  модель файла результатов бенчмарка

    SystemInfo.cs            CPU, GPU, RAM, мониторы, ОС, питание (WMI)

```

## Ограничения

* Во время работы нельзя пользоваться мышью и клавиатурой и блокировать экран — меню игры проходится
  кликами, а детектор старта смотрит на изображение окна.
* Координаты меню измерены для версии бенчмарка 1.0.3.14649. Если разработчики переделают меню, их нужно
  обновить в `BenchmarkRunner.cs` (две константы).
* Полная трассировка лучей в бенчмарке доступна только на NVIDIA RTX.
* На ноутбуках результаты сильно зависят от питания и охлаждения: инструмент предупреждает о работе от
  батареи и показывает в отчёте частоту, мощность и температуру GPU.
